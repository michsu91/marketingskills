# Supporting Content Guide

Covers changelog entries, internal Slack announcements, and sales/CS briefs for launches.

## Changelog Entry

Brief, factual, scannable. This goes on the Imgix changelog or release notes page.

**Structure:**
- Date
- Feature name as heading
- Category tag: `New Feature`, `Enhancement`, `Fix`, `Beta`
- 1-2 sentence description of what changed and the benefit
- Link to documentation

**Example:**
> **Video Previews** (New Feature)
> Generate thumbnail previews from any video using URL parameters. Preview any frame or auto-select the most visually interesting moment.
> [Documentation →]

Keep it factual. The changelog is where developers and power users go for the specifics; save the storytelling for the blog.

## Internal Slack Announcement

Post to #general (company-wide) and #sales (sales-specific context).

### #general Announcement

**Structure:**
1. What launched (1-2 sentences)
2. Why it matters for customers (1 sentence)
3. Link to blog post
4. Link to docs
5. Tag relevant stakeholders (product lead, eng lead)

**Tone:** Celebratory but not over-the-top. Acknowledge the team's work.

**Example:**
> :rocket: **Imgix Video: HLS, DASH & Closed Captions are live**
> Customers can now stream adaptive video and add closed captions through the same URL-based workflow they use for images.
> Blog post: [link]
> Docs: [link]
> Huge props to @max.knowles @christopher.alkhaz and the eng team for shipping this.

### #sales Announcement

More detailed. Sales needs talking points, not just awareness.

**Structure:**
1. What launched (2-3 sentences, slightly more detail)
2. Who it's for (target customer segments)
3. Key talking points (3-5 bullets)
4. Objection handling (if applicable)
5. Pricing/credit implications
6. Demo resources or screenshots
7. Link to docs and blog post

## Sales/CS Brief Document

For major launches, create a standalone brief document (can be a Slack canvas, Confluence page, or shared doc). Include:

**What it is:** 2-3 sentence description of the feature in plain language.

**Who it's for:** Which customer segments benefit most. Be specific: "e-commerce teams managing 10K+ product images" is better than "all customers."

**Key talking points:**
- 3-5 bullet points that a salesperson can use in a call
- Frame around customer problems, not Imgix features
- Include any relevant data points (adoption numbers, performance improvements)

**Pricing:** How this affects credits, what plan level includes it, any upsell opportunities.

**Common objections:**
- Anticipate 2-3 likely objections and provide responses
- Example: "We already use [competitor] for video" → "Imgix Video runs on the same platform as your images, so you get a unified workflow without managing a separate vendor."

**Resources:** Links to docs, demo videos, screenshots, and the blog post.

## Documentation Updates

For every launch, audit whether these pages need updating:
- Feature-specific documentation
- API reference (new parameters, endpoints)
- Pricing/credits page
- Getting started guide
- FAQ

Create a list of pages that need changes and what should be added. If Michelle provides doc links or specs, draft the updates directly.
